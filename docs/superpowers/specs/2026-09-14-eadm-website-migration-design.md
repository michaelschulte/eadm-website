# EADM Website: WordPress → Quarto Migration

- **Date:** 2026-09-14
- **Status:** Approved
- **Source:** WordPress export at `/Users/michael/git_stuff/wp_eadm/eadm-eu-20260914-054440-ujh0nuxckrsu/` (All-in-One WP Migration `.wpress` bundle for https://eadm.eu)
- **Target:** New standalone Quarto website project at `/Users/michael/git_stuff/eadm-website/`, pushed to a new public GitHub repo `eadm-website`

## 1. Goal

Rebuild the public content of the EADM (European Association for Decision Making)
WordPress site as a static Quarto website, preserving the organization's
information architecture and historical content, but with a modern,
easily-restyleable design. The result is committed to git and pushed to a new
GitHub repo. No live deployment (GitHub Pages, custom domain) is configured in
this pass — source only.

## 2. Source data and how it's accessed

The export is an All-in-One WP Migration bundle: `database.sql` (MySQL dump,
table prefix `SERVMASK_PREFIX_`) plus `uploads/`, `themes/`, `plugins/`.
Rather than regex-parsing the raw SQL dump (risky given HTML content contains
commas, quotes, and embedded newlines), the dump has been imported into a
throwaway MariaDB 10.11 Docker container (`eadm_mysql_import`) for reliable
querying. This container is scratch infrastructure for the migration only —
it is not part of the delivered project and gets removed once content
extraction is complete.

Key facts gathered from the imported DB:

| post_type | status | count |
|---|---|---|
| page | publish | 58 |
| page | draft/private | 8 |
| post | publish | 63 |
| post | draft/auto-draft | 7 |
| attachment | inherit | 133 (48 JPEG, 9 PNG, 2 TIFF, 73 PDF, 1 DOCX) |
| nav_menu_item | publish | 31 (reconstructs the live "Main Menu" + "Footer" menu) |

`uploads/` is 493MB total: ~79MB of images (many of which are WordPress's
auto-generated thumbnail sizes of the same source image) and **414MB of PDFs**
(scanned historical SPUDM conference programs 1969–2016, newsletters, meeting
minutes — none over 100MB individually, several 20–60MB).

## 3. Content scope and curation

All 58 published pages and 63 published posts are migrated. Drafts, private,
and auto-draft posts are excluded (they were never public). Beyond that,
exact-duplicate content found in the database is collapsed to a single
canonical copy rather than migrated twice:

- Three near-identical "About EADM" pages (IDs 93, 331, 404 — two are
  byte-identical, the third an earlier near-duplicate draft of the same text)
  → one canonical About page.
- 15 bio pages under the private "The EADM Interview" parent page are
  word-for-word duplicates of 15 posts in the "EADM Interview" category → the
  blog posts are kept (used for the Interview listing), the duplicate bio
  pages are dropped.
- Genuine cruft is dropped: the WordPress-default German "Beispiel-Seite"
  placeholder, an empty "Jobs" page (zero content), and an empty post-payment
  "thanks" redirect page.

Every dropped or merged item, plus any non-obvious placement decision for a
page that had no home in the original nav menu (e.g. "Past Conferences",
"SPUDM 2013", "SPUDM Images", the 2018 Salzburg summer-school report), is
recorded in `CONTENT_AUDIT.md` at the repo root — a generated artifact of the
migration, not hand-maintained — so the curation is reviewable rather than a
silent loss of content.

## 4. Information architecture

The live site's actual navbar was reconstructed from `wp_nav_menu_item` +
`wp_term_relationships` (menu "Main Menu", term id 9). The new site mirrors
that structure:

- **Home** — new landing page (the old WP homepage was just a raw chronological
  post feed via `show_on_front=posts`; a real welcome page with a short EADM
  intro and links into News / Membership / SPUDM replaces it)
- **About EADM ▾** — About, Mission Statement, Code of Conduct, Executive
  Board, Past Executive Boards, President's Column (listing), Contact
- **Membership ▾** — Membership, Mailing List
- **Funding ▾** — Jane Beattie Memorial Travel Scholarship, Workshop Grants
  (+ historical workshop pages 2008–2025), Summer School Reports
- **Prizes ▾** — De Finetti Award, Jane Beattie Scientific Recognition Award,
  Lifetime Contribution Award
- **SPUDM ▾** — History, Past Conferences, SPUDM 2013, SPUDM Images
- **News**, **Newsletter Archive**, **EADM Interview** — top-level items
- Footer: Contact, link to the GitHub repo

"News", "President's Column", and "EADM Interview" become Quarto **listing
pages** (dated, card-style indexes generated by Quarto's `listing:` metadata)
rather than one long flat page each, matching how WordPress presented them as
chronological feeds. "Newsletter Archive" stays a single static page of dated
links (it was never a blog category — just a hand-maintained list of PDF
links in WordPress), pointing at the vendored PDFs (see §6).

## 5. Content pipeline

A one-time Python migration script (kept in the repo under `tools/` for
reproducibility, but not part of the served site) does the conversion:

1. Query the imported MariaDB container for posts/pages/menu structure using
   `JSON_ARRAYAGG(JSON_OBJECT(...))` queries — this returns clean, fully
   escaped JSON in one shot per table, avoiding hand-rolled SQL-value parsing.
2. Build a slug → new-relative-path map for every migrated page/post, from
   the curated content plan in §3–4.
3. For each item's stored content: WordPress's classic editor stores most
   content as blank-line-separated plain text with a few embedded HTML tags
   (`<strong>`, `<a>`, `<table>`, `<img>`), relying on the `wpautop` filter to
   turn blank lines into `<p>` tags at render time — the raw text is *not*
   valid standalone HTML (verified: feeding it to Pandoc's HTML reader
   collapses paragraphs, since bare blank lines are insignificant HTML
   whitespace). Since this same blank-line convention is already valid
   Markdown, and Quarto/Pandoc's Markdown-to-HTML renderer passes embedded
   raw HTML (tables, links, images) straight through untouched (verified),
   the content needs no HTML→Markdown conversion pass at all — it is used
   near-verbatim as the `.qmd` body, with only the targeted regex rewrites
   in steps 4–5 applied.
4. Rewrite internal links (`https://eadm.eu/<slug>/...`) to the new relative
   Quarto paths using the slug map; leave external links untouched.
5. Rewrite `wp-content/uploads/...` media references to the local `images/`
   or `files/` path chosen for that asset (see §6).
6. Emit one `.qmd` file per page/post with YAML frontmatter (`title`, and for
   posts `date`, `categories`).

## 6. Media handling

- **Images** (~79MB raw): WordPress stores multiple auto-generated sizes of
  the same source image (`-150x150`, `-1024x682`, etc.). Only images actually
  referenced by kept content are copied, and only the largest available
  rendition of each — thumbnail-size duplicates are dropped. This should land
  well under the raw 79MB. Copied into `images/`, mirroring the source
  `uploads/YYYY/MM/` layout to keep filenames unambiguous.
- **PDFs** (414MB, 73 files): vendored into the repo as-is under `files/`,
  same `YYYY/MM/` layout, since they're referenced by Newsletter Archive,
  EADM Minutes posts, and Funding/Workshop pages and need to work
  independently of eadm.eu staying online. No single file exceeds GitHub's
  100MB hard limit, so plain git (no LFS) is sufficient.

## 7. Design: modern, and easy to re-skin

The site uses Quarto's standard `website` project type with a **Bootswatch
theme + `_brand.yml`** combination, chosen specifically so the look can be
swapped later with minimal effort:

- `_brand.yml` holds EADM's color palette and typography as named tokens
  (not hardcoded into page content or scattered CSS) — swapping brand colors
  or fonts is a edit to one file.
- `_quarto.yml` sets `theme:` to the `zephyr` Bootswatch base (a current,
  clean, card-friendly default) as a light/dark pair, which gives a built-in
  light/dark toggle in the navbar for free.
- Any custom CSS lives in one small `styles.scss` layered on top of the
  Bootswatch base + brand, instead of being baked into individual pages, so
  changing the base theme name in `_quarto.yml` doesn't require rewriting
  page-level styling.
- A short section in `README.md` documents the two files to edit
  (`_brand.yml` for colors/fonts, the `theme:` key in `_quarto.yml` for the
  base look) to change the site's design.

This is not an attempt to visually replicate the old `twentyeleven`-derived
WordPress theme.

## 11. Out of scope

- Live deployment / custom domain (`eadm.eu`) cutover.
- Replicating WordPress's comment system, contact form backend, or
  membership-payment flow (the "Membership Payment" pages describe a process;
  they are migrated as static informational text only).
- Search functionality beyond Quarto's built-in site search.
